## Completion boundary

This completes the manual inventory/specification review and backlog preparation, not the repair or installation of Hashi. The code currently has confirmed installation, feature and safety defects. No finding is claimed repaired by creating its write-up. The ledger provides coverage of the reviewed baseline; it is not a mathematical guarantee that software contains no undiscovered defects. Newly changed implementation files need fresh review during repair.

Do not revive historical issue checklists as duplicate tasks. Follow the current residual IDs and their expected outcomes/acceptance criteria. Real integration/deployment acceptance must cover fresh installation and upgrade, first-run vault/passkeys, provider readback, actual Traefik/Coraza loading, firewall activation/rescue, scheduled jobs and public HTTPS proxy surfaces.
