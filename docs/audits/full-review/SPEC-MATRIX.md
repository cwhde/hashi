# Specification to implementation matrix — 2026-10-18

All four normative specifications were manually read before the implementation reading. The file ledger covers all710 baseline files. This matrix records what the current implementation actually provides and where that behavior fails the specifications. Original specifications and historical write-ups are preserved.

`requirements.csv` preserves2,937 extracted candidate passages. These are **not2,937 distinct mandatory features**: the extraction also includes schema items, examples, repeated acceptance criteria and references. Every passage now links to one of288 section dispositions in `spec-sections.csv`. The section rows identify current source and relevant confirmed findings; they do not pretend a passing inherited test or a matching class name proves acceptance of every clause.

“Partial” means implementation exists but the linked missing/wrong behavior prevents acceptance. “Implemented structure” describes narrow architecture/workflow presence, not deployment clearance. Test/acceptance sections remain expectations to demonstrate during repairs. UI redesign remains lower priority than installability, missing workflows and significant security problems.
