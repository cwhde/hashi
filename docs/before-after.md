# Hashi — before and after

Three views: the V2 attempt vs the new plan, the production setup today vs after Hashi, and exactly which behaviours
changed in the spec. "Unchanged" means the feature behaves as originally specified.

## 1. V2 attempt vs new plan

| Area | Before (V2, 2026-05 → 06) | After (restart) | Why |
| --- | --- | --- | --- |
| Backend | .NET 10, EF Core, ASP.NET Minimal APIs | Go, net/http, sqlc | One language with Pulse; one static binary |
| Database | PostgreSQL 18 (separate container) | SQLite in WAL mode, one file | No DB server to run/upgrade; homelab scale |
| Frontend | "SvelteKit 5", shadcn-svelte | Svelte 5 / SvelteKit 2 SPA embedded in the binary, shadcn-svelte | Same UI stack, correct versions, one container |
| Pulse agent | Go (then a PR rewrote it to .NET AOT) | Go | Spec required Go |
| Containers | 2 (app + Postgres) | 1 | Simpler deploy and backup |
| Spec format | 1 base spec + 3 addenda (~5,300 lines), contradictions resolved by "later wins" | 12 area files (~1,900 lines), addenda merged in, no "later wins" | An agent reads only the area it works on |
| API contract | Generated from C# code | Spec-first `openapi.yaml`, server + TS client generated | Contract can't drift silently |
| External APIs | Written from memory/docs | Captured from the real system first (`testdata/contracts/`) | V2's adapters hit a shut-down API and a nonexistent CLI command |
| DNS provider | Legacy Hetzner DNS API | Hetzner Cloud API (zones/RRSets) behind a provider interface | Legacy API shut down 2026-05-27 |
| ACME DNS-01 | Hetzner token on every Traefik host | Traefik asks Hashi (`httpreq`); token stays in Hashi | One secret in one place, works with any DNS provider module |
| Vault | Passkey-PRF "admin vault" + Docker-secret service vault at the same time | One master key (Docker secret) + recovery key; optional strict mode (PRF/recovery unlock) | V2's PRF path protected nothing extra and never worked |
| Delivery | 14 phases, all built in parallel, never deployed | 13 slices, one at a time, each must work on the real servers (prod-proof) before the next | V2 had 450 commits and zero deployments |
| Quality loop | 8 AI audit series → 353 issue files → 184 open findings | One review per change against the spec, max 10 findings, only reproduced ones fixed, no audit series | Fixing every finding created new findings |
| Agent guardrails | None | `CLAUDE.md`, 6 project skills, read-only reviewer agent, hooks (check gate with 3-try cap, secret guard, remote-command guard), `frontend-design` + `superpowers` plugins | Rules that must hold are enforced by the harness, not by prompts |

## 2. Production today vs after Hashi

| Function | Today | After Hashi |
| --- | --- | --- |
| Public DNS records | V1 Hashi (Node) writes CNAMEs every 5 min from a topology TXT record + Pangolin's resource list | Hashi, from its own resources and host records; TXT record no longer needed |
| Reverse proxy (VPS) | Traefik container in the Pangolin LXC, config from Pangolin's HTTP provider + badger auth plugin | Hashi-installed Traefik on a fresh LXC, Hashi static + dynamic config; Pangolin and its Traefik deleted |
| Reverse proxy (home) | Native Traefik on Alpine with a copy of Pangolin's config, routes pulled from Pangolin | Hashi-installed Traefik with Hashi config; old config removed |
| Edge auth | Pangolin badger | Hashi forward auth + edge SSO (Pocket ID as IdP) |
| Firewall (VPS) | `/scripts/firewall.sh` via cron every 15 min; ~30 duplicated FORWARD rules have piled up | Hashi-generated script in Hashi chains, check-before-insert, rescue timer; old chains and cron removed in the first apply |
| Firewall (home) | None on the host; home router forwards; traffic enters via the VPS | `external_nat` mode: no firewall management, DNS routes via the VPS (as today) |
| Internal DNS | 2 AdGuard instances, adguardhome-sync copies origin → replica every 10 min | Hashi writes its rewrites to both instances; adguardhome-sync retired |
| Monitoring | Gatus with 41 endpoints generated by V1 | Built-in monitoring + public status page; Gatus retired |
| App dashboard | — | Public app dashboard |
| Abuse / WAF / blocklists | CrowdSec log path configured on the home Traefik, no CrowdSec process found | Hashi security engine, Coraza WAF, CAPTCHA, blocklists |
| CAPTCHA | wicketkeeper on its own port | Cap per spec (open question: keep Cap or support wicketkeeper) |

## 3. Spec behaviour changes (complete list)

| Change | Type | Effect on your original idea |
| --- | --- | --- |
| Tech stack (Go/SQLite/SPA) | Changed | Same features |
| Vault: one master key, strict mode optional | Changed mechanism | Same protections offered; unattended sync still the default |
| ACME DNS-01 via Hashi (`httpreq`) | Changed mechanism | Keeps DNS providers swappable; Traefik hosts hold no DNS token |
| `external_nat` edge mode | Added | Needed for the home host; nothing removed |
| Firewall: loopback DNAT, corosync MTU routes, `/etc/hosts` pins, cleanup of the old script's chains | Added | Behaviours of your current script the old spec said to keep but didn't list |
| DNS ownership marker as an optional provider capability (Hetzner uses RRSet labels) | Refined | DB stays authoritative; providers without markers just skip it; swapping/adding a provider stays one module |
| Change-protected RRSets are read-only | Added | Respects a Hetzner-side safety flag |
| AdGuard: Hashi writes every instance itself | Clarified | Replaces adguardhome-sync |
| Cutover: replace Pangolin, both Traefik instances, Gatus, adguardhome-sync, firewall script | Clarified | Full replacement, nothing adopted |
| Everything else | Unchanged | — |
