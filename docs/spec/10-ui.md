# 10 — UI: information architecture, design system, themes

Supersedes V2 §22 (Shades of Purple) and carries over the V2 UI design-foundation addendum.

## 1. Information architecture

Navigation groups (one expandable level max):

- **Operate:** Overview, Resources, Status, Security, Activity
- **Edge:** DNS, Traefik, Firewall Hosts, Pulse
- **Configure:** App Display, Scripts, Connections, Settings

Shell: fixed left navigation (expanded 224–240 px, collapsed rail 60–68 px; collapsed by default, hover expands, pin keeps
open), compact top context bar (48–56 px: breadcrumbs, pending-sync indicator, vault lock state, theme, account menu —
never duplicates the page title), one independently scrolling content region, optional right drawers.

Overview widgets (toggle + reorder in Settings → Appearance): resource health summary, firewall host availability,
Traefik sync state, DNS sync state, recent incidents, active security events, pending sync changes, certificate expiry
warnings, vault lock state, recent audit entries.

Pending high-risk plans are surfaced on login and in the context bar.

## 2. Design philosophy

Calm operations: show what is healthy, what needs attention, what changed, what action is available and what risk it
carries. Overview before detail (progressive disclosure via expandable rows, drawers, popovers, tabs, "Advanced" sections,
context menus — never hiding status, destructive consequences, validation failures or required actions). Dense, not
cramped. Consistent rounded geometry (pills only for status, filters, segmented controls, tags, toggle tracks). Quiet
surfaces (no heavy shadows, strong gradients, neon, glass everywhere, competing accents, decorative backgrounds behind
data). Immediate and trustworthy (local feedback same frame; never imply remote success before the API confirms).

Rejected direction: HUD frames, corner brackets, scan lines, glows, fake terminals, luminous gradients, radar visuals,
floating unaligned islands, a card per number, pill containers, mixed sharp/rounded, hero headers, futuristic animation,
accent on every surface. No marketing landing page. No nested cards.

References distilled (images not required): Pocket ID (rounded panels, calm forms), Cloudflare (navigation discipline,
dense tables, inline row editing), Pangolin (resource-list hierarchy, single primary action), NetBird (width efficiency),
Gatus (status history strips), Nezha (equal chart grids, compact metrics), Claude (warm palette construction),
Visual Studio dark violet (near-black depth, yellow accents), Verdant mock (green-black + yellow execution).

| Toolbar / control height | 32–36 px |

Content starts within 24–32 px of the top bar. Settings forms max ~1120–1280 px wide; tables/grids/charts may use full width.
Density budget: ≥85 % neutral surfaces, accent ≤ ~5 %, semantic colours only for state, ≤1 large + 2 small panels competing
for first attention, ≤1 filled primary action per toolbar, explanations ≤2 lines, ≤3 surface elevations.

## 4. Tokens

All styling resolves through semantic tokens; components contain no theme literals and never branch on theme names.
Theme on `<html data-theme="…">`. Token groups: canvas/shell, surface levels, text levels, borders, accent (+fg, hover),
focus, selection, success/warning/danger/info, chart series, scrim/overlay, radius, spacing, motion.

Radius: `--radius-xs` 6 (badges, chips, tooltips) · `-sm` 10 (inputs, compact buttons) · `-md` 14 (buttons, menus, table
containers) · `-lg` 18 (panels, cards, drawers) · `-xl` 24 (dialogs, major tools) · `-pill` 999. No one-off radii.
Spacing: 4 px base (4, 8, 12, 16, 20, 24, 32, 40). Grid: 12 columns, 12–16 px gutters (4+4+4, 8+4, 9+3, 6+6, 12);
<1200 px three→two columns; <800 px one column; forms keep two columns down to ~900 px if fields stay ≥320 px.

Stable dimensions: icon button 32×32, control 36, prominent control 40, nav row ≥36, status dot 8. Loading, hover,
badges and errors never resize rows or toolbars.

Character: Graphite = black/charcoal with small blue signals; Warm Linen = cream and warm gray with clay signals, crisp
near-white inputs, never beige-on-beige or cool gray; Verdant = green-black with yellow signals (optional static,
extremely low-contrast edge glow only); Violet Night = near-black with violet undertone and yellow signals, much darker
than the old Shades of Purple.

Semantic colours (independent of theme, lightness may be tuned per theme): success `#22C55E`, warning `#F59E0B`, danger
`#EF4444`, info `#38BDF8`. Colour is never the only signal (pair with text/icon/shape). Yellow accents never stand in for warning.

Accent is used for: the single primary action in a bounded area, active navigation (8–14 % tint + foreground text),
selected tabs/segments, focus, links, principal non-semantic chart series. Not for icons, panel borders, body text,
backgrounds, or state messages. Hover = one surface level or 4–8 % foreground tint, never a new hue.

Automated tests verify WCAG contrast for text, muted text, accent/accent-fg and focus pairs in every theme.

### 5.1 Custom themes

Basic editor: canvas, surface, text, muted text, border, accent, optional chart accents, radius preference (within the
rounded range), transparency preference; advanced token overrides behind a separate section. Live preview without commit;
cancel returns to the saved theme; reset to any default; contrast validation before save; invalid/incomplete themes fall
back safely; versioned JSON (import/export) so new tokens get defaults; theme applied before first paint (inline boot
script reading a cookie/localStorage copy) — no flash of wrong theme.

## 6. Surfaces, typography, components

- Surface hierarchy ≤4 levels per view (canvas, shell, content, elevated). Strong border *or* strong surface change, not both.
- Shadows only on overlays/menus/drawers/dialogs. Transparency only on sticky chrome, menus, drawers, dialogs, small
  floating toolbars (88–96 % opacity, ≤16 px blur, opaque fallback and reduced-transparency setting).
- Typography: system sans-serif; body 14 px; dense metadata 12 px; page titles 24–28; panel titles 14–16; table headers
  12–13 medium and quieter than content; monospace for IPs, ports, IDs, hashes, paths, code; letter-spacing 0; no viewport
  font scaling; uppercase only for very short category labels.
- Panels: 18 px radius, 1 px border, surface 1, no shadow, 20 px padding (16 compact); header = 16 px icon + title + optional
  one-line description + right actions. Repeated cards: identity top-left, status/overflow top-right, metadata below,
  primary action bottom-right, equal min height. Banners: 12–16 px radius, icon + title + ≤2 lines + optional action/dismiss;
  warnings use tinted border/icon/title, not saturated fills.
- Tables are the default for scannable data: stable columns, identity/state first, one primary row action or overflow,
  inline editing (expands under the row across full width, 160 ms; save+cancel together, delete separate; closes only on
  explicit cancel/save/confirmed navigation) or a right drawer for large forms; empty/loading/error/filtered-empty/partial
  states; optional column visibility; intentional, keyboard-accessible horizontal overflow. Anatomy: summary/warning →
  toolbar (search 280–360 px, filters, then refresh/import/export/display options/primary add right-aligned) → header →
  rows → inline editor → footer (count, page size, pagination).
- Forms: labels above controls; help text explains consequences/formats; shared grids; advanced fields collapsed; field and
  form-level validation; destructive settings separated; sticky save only for long forms; toggles for immediate binary
  settings; checkboxes for multi-select/acknowledgement; proper selects/comboboxes/segments/sliders/steppers. Inputs 40 px,
  10–14 px radius, 12 px padding, 6 px label/help gaps, 16–20 px field gaps, 16–24 px column gaps; textareas 96–128 px;
  code/YAML always CodeMirror. Settings page = Pocket-ID-style large panel per concern, two-column grid, toggles beside
  their label/explanation, advanced collapsed at bottom, save bottom-right.
- Buttons: primary / secondary / ghost / outline / destructive with theme-independent hover, pressed, pending, disabled,
  focus. Icon-only buttons: square hit area, accessible name, tooltip when not obvious, stable icon during pending.
  Overflow menus never hide the routine primary action.

Required shared primitives before page work: app shell, nav group/item, page header, toolbar, panel, banner, metric
summary, status pill, data table + toolbar, inline row editor, empty/error/loading states, settings section, form field +
help, advanced disclosure, segmented control, dialog, right drawer, popover/overflow menu, chart panel, status history
strip. Pages never re-create their padding/border/radius.

## 7. Motion

CSS transitions and Svelte transitions only (no animation library). Durations: hover/press 80–120 ms; menus 100–140;
row/advanced expansion 140–180; drawer/dialog 160–220; page content 120–180; >250 ms needs a reason. Animate opacity,
transform, grid-rows/measured height, border/background colour; never large shadows, filters, full-page blur.
One ease-out (`cubic-bezier(0.2,0.8,0.2,1)`) and one ease-in (`cubic-bezier(0.4,0,1,1)`); exits 20–30 % shorter;
no action waits for an exit animation. Specific: sidebar group 160 ms height+opacity; advanced disclosure 160; inline editor
160; popover 4 px translate + opacity 120; dialog opacity + scale .98→1 180; drawer 12–20 px translate + opacity 200; tab
content opacity 100 (no horizontal slide); toggle thumb 120; button press ≤1 px / surface change 80.
`prefers-reduced-motion`: spatial → immediate or opacity-only, no chart animation, no decorative motion.

## 8. Loading and errors

Feedback < 100 ms; no spinner for near-instant actions (subtle pending state); skeletons only when layout is known and
load > ~200 ms; keep content visible during background refresh; mark stale data; errors say what failed and whether retry
is safe; toasts only for transient confirmation; optimistic updates only when rollback is clear and not security-sensitive.

## 9. Charts

uPlot for time series; SVG/CSS for strips, sparklines, progress. No other chart library without a proven need. Colours
resolved from CSS variables at render time (no hard-coded hex in chart code). Flat fills (0–12 % area opacity), ≤4
emphasized series, subordinate axes/grids (1 px low contrast), legend when >1 series, hover/keyboard values, units shown,
missing ≠ zero, status colour only for status, stable height while loading. Primary stroke 1.5–2 px, secondary 1–1.5,
points on hover only, axis labels 11–12 px. Principal series: blue (Graphite), clay (Warm Linen), yellow (Verdant, Violet Night).
Chart panel: title top-left, current value top-right, optional range segment, plot, legend. Nezha-style grids share
heights and baselines. Gatus-style strips: samples 3–5 px wide, 1–2 px gaps, ≤3 px radius, semantic colours incl. missing,
accessible text summary. Multi-service latency: equal-width summary cells above one wide chart.

## 10. Responsive and accessibility

Desktop-first, all workflows usable on mobile: fewer columns before smaller type; mobile stacks toolbars/forms, keeps
primary actions visible; tables scroll purposefully or become structured rows (no silently dropped columns); drawers/dialogs
fit and scroll; safe areas respected; no overlaps; touch targets ≥40 px (never <32). WCAG 2.2 AA: contrast in all themes,
visible focus, full keyboard operation, managed focus in dialogs/drawers/menus/inline editors, errors programmatically
associated, polite live regions, chart text summaries, tooltips never sole source, reduced motion and transparency honoured.

## 11. Performance

No animation framework; no permanent large backdrop blur; lazy-mount charts and heavy tools; destroy chart instances and
observers on unmount; never re-render a whole table for one row; virtualize only when justified; no decorative image
fetches on admin screens; theme switch updates CSS variables only; UI works without animation/transparency.

## 13. Delivery note

Tokens, Graphite and all primitives are built in S0/S1 and used from the first page. The other three themes and the
custom-theme editor are slice S11 — they reuse the same tokens, so no page is restyled later.
