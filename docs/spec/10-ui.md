# 10 — UI

This file holds **what the UI should feel like and contain**. Exact layout, sizes, spacing and component rules are not
fixed here: they are produced in the UI design slice (S0b, 11-delivery.md) for all features at once, before feature
slices build pages, so the interface is designed for the full feature set from day one. The result is
[10b-ui-system.md](10b-ui-system.md) plus the clickable mocks under `/design` in the SPA.

## 1. Design intent

- A calm, modern, **rounded** operational interface — a precise control surface for infrastructure, not a marketing
  dashboard or a demo.
- **Dense but not cramped**: lots of operational information on screen, organised by hierarchy and alignment rather than
  tiny controls.
- **Overview before detail**: routine decisions possible without opening another screen; history, raw data and advanced
  options behind expandable rows, drawers, tabs or "Advanced" sections — never hiding status, risk or errors.
- **Quiet surfaces**: hierarchy from spacing, type and subtle borders; colour only where it carries meaning; one primary
  action per area.
- **Immediate and trustworthy**: every input acknowledged at once; never show a remote change as done before the API confirms.
- Inline editing for short records (DNS-style rows expanding in place), drawers for larger forms.
- Gatus-style status history strips and Nezha-style metric/chart grids for monitoring and security.

### 1.1 Rejected direction

The earlier proposals were rejected for looking like a low-budget science-fiction interface. Avoid: HUD frames, corner
brackets, scan lines, glows, fake terminals, neon or luminous gradients, glass on every panel, radar/ring visuals without
operational value, a card for every number, floating unaligned islands, mixed sharp and rounded shapes, hero headers that
push data below the fold, futuristic animation, accent colour on every surface.

### 1.2 References

Pocket ID (rounded panels, calm forms), Cloudflare (navigation discipline, dense tables, inline row editing), Pangolin
(resource list hierarchy), NetBird (width efficiency for large sets), Gatus (status strips), Nezha (compact metrics, chart
grids), Claude (warm palette construction), Visual Studio dark violet (near-black depth, yellow accents), and a Verdant
mock (green-black with yellow). Written descriptions of the reference screenshots: [10a-ui-references.md](10a-ui-references.md).

Character: Graphite — black/charcoal with small blue signals. Warm Linen — cream and warm grey with clay signals, crisp
light inputs, never beige-on-beige. Verdant — green-black with yellow signals. Violet Night — near-black with a violet
undertone and yellow signals (much darker than the old Shades of Purple).

Status colours are independent of the theme: success green, warning amber, danger red, info blue — and never the only signal.

**Custom themes**: the user can create a theme (canvas, surface, text, muted text, border, accent, optional chart colours,
roundness and transparency preference), preview it without saving, reset to any built-in theme, and import/export it.
Hashi refuses to save a theme with unreadable contrast and falls back safely if stored theme data is invalid.

## 3. Information architecture

Navigation destinations (from the original spec, updated by the security model): Overview, Services, DNS, Traefik, Firewall Hosts, Pulse, Security, IP sets, Rule sets, Status,
App Display, Security, Scripts, Connections, Activity, Settings. Collapsible left navigation (hover to expand, pin to
keep open). Grouping, page layouts and per-page contents are designed in S0b.

Overview widgets (toggle + reorder in settings): service health, firewall host availability, Traefik sync state, DNS
sync state, recent incidents, active security events, pending sync changes, certificate expiry warnings, vault lock
state, recent audit entries. Pending high-risk plans are surfaced on login.

Activity includes a live log view (filter by subsystem/level, secrets redacted) and per-subsystem sync history.

## 4. Stack and quality bar

- shadcn-svelte on Bits UI as the only component system; Tailwind CSS v4; Lucide icons; uPlot for charts; CodeMirror 6 for YAML/shell.
- Use the `frontend-design` plugin for design work.
- Components use theme tokens only — no colours hard-coded in components, so all themes and custom themes work everywhere.
- WCAG 2.2 AA, full keyboard use, visible focus, reduced-motion and reduced-transparency preferences honoured.
- Usable on mobile; desktop-first.
- No flash of the wrong theme on load.
- Visual tests (Playwright screenshots) of the key pages in every built-in theme at desktop and mobile width.
